# ดึงข้อมูลแบบ local-first: ใช้ yt-dlp, faster-whisper และ PaddleOCR ในเครื่อง

Ingest ใช้ `yt-dlp` ดึงรายการคลิป ซับ และวิดีโอ 360p ถ้าไม่มีซับหรือซับแย่ ถอดเสียงด้วย `faster-whisper large-v3` บน GPU ในเครื่อง (RTX 4070) ส่วน On-screen Text ใช้ ffmpeg ตัดเฟรมตามการเปลี่ยนฉากแล้ว OCR ด้วย PaddleOCR ใช้ API ภายนอกแบบเสียเงิน (NexLev) เฉพาะเป็นทางสำรองรายคลิปเมื่อ yt-dlp ถูกบล็อก เลือกแบบนี้เพราะช่องหลักพันคลิปถ้าใช้ API จะแพงมาก ในขณะที่เครื่องนี้มี GPU พอ ข้อเสียที่ยอมรับคือช้ากว่า และต้องคอยอัปเดต yt-dlp เมื่อ YouTube เปลี่ยนระบบ

## Considered Options

- **NexLev/vidIQ เป็นแหล่งหลัก:** ไม่โดนบล็อก แต่ใช้เครดิตต่อคลิป และไม่มีข้อความจากภาพ
- **OpenAI/Groq Whisper API:** เร็ว แต่เสียเงินตามจำนวนนาที และต้องส่งไฟล์เสียงออกนอกเครื่อง
- **ให้ AI ดูทุกเฟรม (vision):** แม่นกว่า OCR แต่แพงและช้ากว่าหลายเท่า เก็บไว้เป็น option `--vision` เท่านั้น

## Update 2026-11-08 (ผล prototype ขั้นที่ 1)

- **Transcript:** ภาษาอังกฤษใช้ซับของ YouTube ได้เลย เพราะต่างจาก Whisper แค่ 2–5% ส่วนภาษาไทยถอดเสียงด้วย Whisper large-v3 ทุกคลิป เพราะซับอัตโนมัติภาษาไทยผิดเยอะ
- **On-screen Text:** ปิดเป็นค่าเริ่มต้น เปิดเป็นรายช่องด้วย `--screen-text` เมื่อเปิดใช้ ให้คัดเฉพาะเฟรมที่เปลี่ยนฉากใหญ่ แล้วให้ Claude ดูภาพแทน OCR ที่มาของการตัดสินใจนี้: PaddleOCR บน CPU ใช้เวลา 7–10 วินาทีต่อเฟรม อ่านภาษาไทยผิดหลายคำ และในช่องทำอาหารได้ข้อมูลใหม่แทบไม่มี (ดู `docs/research/0002-phase1-prototype.md`)
